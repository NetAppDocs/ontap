= ONTAP ARP supported configurations
:icons: font
:imagesdir: ../media/

[.lead]
Autonomous Ransomware Protection (ARP) is available for NAS workloads beginning with ONTAP 9.10.1 through ONTAP 9.15.1. Before deploying ARP, you should be aware of the recommended uses and supported configurations as well as performance implications.

NOTE: If you are running ONTAP 9.16.1 or later, see link:support-arpai.html[Supported configurations for ARP/AI].

== Suitable workloads

ARP is suited for these types of workloads:

* Databases on NFS storage
* Windows or Linux home directories
+
Users could create files with extensions that weren't detected in the learning period, so there is a greater possibility of false positives in this workload.
* Images and video
+
For example, health care records and Electronic Design Automation (EDA) data

== Unsuitable workloads

ARP is not suited for these types of workloads:

* Workloads with a high frequency of file create or delete operations (hundreds of thousands of files in a few seconds; for example, test/development workloads).
+
ARP's threat detection depends on its ability to recognize an unusual surge in file create, rename, or delete operations. If the application itself is the source of the file activity, it cannot be effectively distinguished from ransomware activity.
* Workloads on volumes with more than 4,000 unique file extensions.
+
ARP (9.10.1–9.15.1) can analyze up to 4,000 file extensions per volume. If the number of unique file extensions on a volume exceeds this limit, ARP cannot efficiently detect ransomware activity and the workload is considered unsuitable.
* Workloads where the application or the host encrypts data.
+
ARP depends on distinguishing incoming data as encrypted or unencrypted. If the application itself is encrypting the data, then the effectiveness of the feature is reduced. However, ARP can still work based on file activity (delete, overwrite, or create, or a create or rename with a new file extension) and file type.
* SAN workloads.
+
ARP (9.10.1–9.15.1) does not support SAN volumes. SAN support was introduced with ARP/AI in ONTAP 9.17.1.

== Supported configurations

ARP (9.10.1–9.15.1) supports NAS workloads across NFS and SMB protocols on FlexVol volumes and, beginning with ONTAP 9.13.1, on FlexGroup volumes.

[options="header"]
|===
| Configuration | ONTAP 9.15.1 | ONTAP 9.14.1 | ONTAP 9.13.1 | ONTAP 9.12.1 | ONTAP 9.11.1 | ONTAP 9.10.1
| FlexVol volumes (NAS) | ✓ | ✓ | ✓ | ✓ | ✓ | ✓
| FlexGroup volumes (NAS) | ✓ | ✓ | ✓ | | |
| Volumes with SnapMirror asynchronous | ✓ | ✓ | ✓ | ✓ | | 
| SVMs with SnapMirror asynchronous (SVM DR) | ✓ | ✓ | ✓ | ✓ | |
| SVM data mobility (`vserver migrate`) | ✓ | ✓ | ✓ | ✓ | |
| Multi-admin verification (MAV) | ✓ | ✓ | ✓ | | |
| MetroCluster configurations | ✓ | ✓ | ✓ | ✓ | ✓ | ✓
|===

NOTE: SnapMirror synchronous and SnapMirror active sync are *not* supported with ARP (9.10.1–9.15.1). These configurations are supported only with ARP/AI beginning in ONTAP 9.19.1.

[[snapmirror]]
== SnapMirror and ARP interoperability

For ONTAP 9.12.1 and later, ARP is supported on volumes protected with SnapMirror asynchronous replication. SnapMirror synchronous and SnapMirror active sync are not supported.

If a SnapMirror source volume is ARP-enabled, the SnapMirror destination volume automatically acquires the ARP configuration state (enabled/disabled and mode) of the source volume. The destination does not need to be separately enabled for ARP.

While a destination volume consists of read-only (RO) snapshots, no ARP processing is done on its data. However, when a SnapMirror destination volume is converted to read-write (RW), ARP is automatically enabled on the RW-converted destination volume.

== Performance and volume limits

ARP has minimal performance impact under tested conditions with FlexVol volumes. The impact depends on the type of workload: write-heavy workloads may experience up to a 4% reduction in throughput.

The following volume limits apply to ARP (9.10.1–9.15.1):

[cols="2,1"]
|===
| Volume type | Limit per node (AFF systems)
| FlexVol | 150 volumes
| FlexGroup members (cumulative per node) | 60 volumes
|===

== [[multi-admin-verification]]Multi-admin verification with ARP-protected volumes

Beginning with ONTAP 9.13.1, you can enable multi-admin verification (MAV) so that two or more authenticated user admins are required to approve certain ARP configuration operations, such as:

* Disabling ARP on a volume
* Deleting ARP snapshots
* Modifying ARP snapshot policy

link:../multi-admin-verify/enable-disable-task.html[Learn more about enabling MAV].
