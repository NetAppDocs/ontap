= Modify a volume's cloud retrieval policy
:icons: font
:imagesdir: ../media/

[.lead]
When using the 'Auto' volume tiering policy, if cold blocks are read sequentially, they stay cold and remain on the cloud tier. For most client applications this is desirable behavior and prevents deep file scans common to antivirus and analytics applications from writing cold data back to the local tier

Beginning in ONTAP 9.8, you can change a volume's cloud retrieval policy to override the link:tiering-policies-concept.html#how-cloud-retrieval-policies-work-with-tiering-policies[default cloud retrieval] behavior. 

.Before you begin

* Modifying a volume using the `-cloud-retrieval-policy` option requires ONTAP 9.8 or later.
* You must have the advanced privilege level to perform this operation.
* You should understand the behavior of tiering policies with `-cloud-retrieval-policy`.
+
link:tiering-policies-concept.html#how-cloud-retrieval-policies-work-with-tiering-policies[How cloud retrieval policies work with tiering policies]

.Step

. Modify the cloud retrieval policy for an existing volume by using the `volume modify` command with the `-cloud-retrieval-policy` option:
+
----
volume create -volume <volume_name> -vserver <vserver_name> - tiering-policy <policy_name> -cloud-retrieval-policy
----
+
----
vol modify -volume fp_volume4 -vserver vs0 -cloud-retrieval-policy promote
----
