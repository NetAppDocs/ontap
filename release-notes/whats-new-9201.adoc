= What's new in ONTAP 9.20.1
:icons: font
:imagesdir: ../media/

[.lead]
Learn about the new capabilities available in ONTAP 9.20.1.

For details about known issues, limitations, and upgrade cautions in recent ONTAP 9 releases, refer to the https://library.netapp.com/ecm/ecm_download_file/ECMLP2492508[ONTAP 9 Release Notes^]. You must sign in with your NetApp account or create an account to access the Release Notes.

== Data protection 

[cols="30%,70%",options="header"]
|===
| Update | Description
a|
xref:../data-protection/cloud-backup-with-snapmirror-task.html[SnapMirror cloud support for in-place restore to original source volume]
a|
SnapMirror cloud supports in-place restore operations for FlexVol volumes, enabling you to perform a cloud snapshot restore operation directly back to the original source volume. ONTAP selects the latest common snapshot and performs an incremental transfer, reducing restore time.

//ONTAPDOC-4032
a|
xref:../snapmirror-active-sync/limits-reference.html[Increased SnapMirror active sync object limits]
a|
SnapMirror active sync increases the number of volumes supported per HA pair to 600 for SAN and NAS configurations.

//ONTAPDOC-4173
a|
xref:../snaplock/snapshot-lock-concept.html[Tamperproof snapshot support with SnapMirror active sync NAS]
a|
ONTAP adds support for tamperproof snapshots with SnapMirror active sync NAS FlexVol volumes. This enhancement lets customers combine SnapMirror active sync NAS availability with immutable snapshot protection.

//ONTAPDOC-4351
a|
xref:../data-protection/modify-svm-dr-dest-vol-capacity.htm[Enhanced SVM disaster recovery]
a|
ONTAP enhances SVM disaster recovery by allowing selected volume modify attributes on SVM-DR destination volumes using standard admin privilege volume modify workflows, reducing the need for Support-assisted procedures.

ONTAP also extends opt-in SVM-DR Quick Resync support to FlexGroup constituents, helping large FlexGroup-bearing SVMs to return to a protected state faster after DR rehearsal, resync, or flip-resync workflows
xref:../data-protection/resync-svm-destination-task.html[Resynchronize the data on an ONTAP SnapMirror destination SVM]

//ONTAPDOC-4305
a|
xref:../data-protection/configure-backend-fc-replication.html[Backend support for SnapMirror replication over FC] 
a|
You can configure backend SnapMirror asynchronous replication and SnapLock for SnapVault over existing Fibre Channel (FC) fabrics.

This allows replication traffic to travel entirely within existing SAN infrastructure without introducing IP networks between the source and destination cluster. Prior to ONTAP 9.20.1, traffic for these replication relationships is carried exclusively over the intercluster IP network.

//ONTAPDOC-3949
a|
xref:../consistency-groups/protect-task.html[Consistency group replication from non-snapLock source volumes to SnapLock for SnapVault destination volumes]
a|
You can replicate consistency groups from a non-SnapLock source volume to a SnapLock for SnapVault destination volume. SnapLock for SnapVault protects the replicated consistency groups from accidental or malicious deletion.

//ONTAPDOC-4048
a|
xref:../san-admin/fc-sp-3-security-support.html[FC-SP-3 authentication and encryption with Broadcom secure HBAs]
a|
ONTAP supports Fibre Channel Security Protocol 3 (FC-SP-3) authentication and encryption on Broadcom secure HBAs with AFF and FAS systems. FC-SP-3 support enables hardware-level end-to-end encryption and device authentication to protect data in flight between FC and NVMe/FC SAN hosts and ONTAP storage systems while aligning with T11 Fibre Channel security standards.

Encryption is offloaded, so there is no performance impact on your storage system.

//ONTAPDOC-3966

xref:../nas-audit/supported-file-operation-filter-fpolicy-nfsv4-concept.html[FPolicy support for NFS 4.2]

This feature provides non-disruptive monitoring without impacting performance.

== Security  

[cols="30%,70%",options="header"]
|===
| Update | Description 
a|
Apache fair queueing for management connection floods and precluster enhancements
a|
ONTAP introduces opt-in, default-off, source-IP fair queueing on the management web server to help maintain access to REST, System Manager, and ONTAPI during management connection floods. ONTAP also supports image installation through a precluster-only REST API and enhances Dynamic Host Configuration Protocol (DHCP) handling so the precluster node-management LIF remains available through lease renewals and IP address changes while the node awaits cluster setup.

//ONTAPDOC-4161
a|
xref:../modify-snapshot-options-arpai.html[Enhanced controls for ARP/AI snapshot response policies]
a|
You can configure the ARP/AI snapshot response policy at the SVM or volume level to control whether ARP/AI creates snapshots when it detects abnormal activity. Three policies are available: `alert-with-proactive-and-periodic-snapshot` (default, preserves existing behavior), `alert-with-proactive-snapshot` (attack snapshots only, no periodic snapshots), and `alert-only` (alerts and event logs only, no snapshots created). After an upgrade to 9.20.1, the default periodic snapshot maximum count changes from 6 to 2, and the default retention period changes from 12 to 7 hours, unless those node-level options were previously modified.

//ONTAPDOC-4059
a|
xref:../encryption-at-rest/enable-external-key-management-96-later-nve-task.html[Key management workflow improvements for data SVMs]
a|
When you enable an external key manager on a data SVM, ONTAP can automatically migrate that SVM's volume encryption keys from the admin-scope key manager to the new data-SVM key manager. This simplifies the transition to external key management and removes the need for a separate manual migration step in the standard workflow.

//ONTAPDOC-3992
a|
xref:../multi-admin-verify/index.html[Support for IdP, AD, and LDAP groups as MAV approvers]
a|
MAV approval groups can include identity provider (IdP), Active Directory (AD), and LDAP (nsswitch) groups as approvers, in addition to individual administrators. Supported group types include Entra ID, ADFS, AD domain groups, and LDAP groups. Adding or removing users in the IdP, AD, or LDAP directory does not require any changes to the MAV configuration. Changes to a user's group membership take effect after re-authentication at the user's next login. You can use the security multi-admin-verify registered-operations show command to display all MAV-protectable operations available on the current cluster.

//ONTAPDOC-3973
|===

== Storage resource management enhancements  

[cols="30%,70%",options="header"]
|===
| Update | Description 
a|
xref:../s3-config/delete-recover-bucket-with-data.html[Support for deleting ONTAP S3 buckets that contain objects]
a|
Administrators can schedule deletion of buckets containing objects when using a configurable retention-based recovery window. This enables bucket recovery before the retention window expires. The feature reduces expiration backlog and makes capacity reusable faster for high-churn workloads.

//ONTAPDOC-3999
a|
xref:../flexcache/sizing-concept.html[FlexCache sizing limits increase]
a|
The FlexCache fanout limit is raised to 200 caches per origin and writeback caches per origin is raised to 50. Volume-count cutoffs are removed where possible so practical limits align with ONTAP system volume limits.

//ONTAPDOC-4180
a|
xref:../flexcache/supported-unsupported-features-concept.html%23supported-features[NVFail support with FlexCache]
a|
You can create FlexCache relationships with NVFAIL-enabled origins. You can also enable NVFAIL on cache volumes, independent of origin volumes. On origin or cache volumes where NVFAIL has occurred, ONTAP blocks data reads or mutations while preserving write-back of modified cached data, and normal I/O resumes after recovery.

//ONTAPDOC-4237
a|
xref:../flexgroup/definition-concept.html[Simplified FlexGroup capacity management]
a|
ONTAP simplifies FlexGroup provisioning and capacity management by reducing the need for administrators to manage constituent volumes, improving capacity balancing behavior, and recommending FlexVol-to-FlexGroup conversion earlier in the volume lifecycle through EMS alerts and CLI prompts.

//ONTAPDOC-4242
a|
xref:../svm-migrate/index.html#supported-and-unsupported-features[SVM migration support for S3 NAS buckets]
a|
ONTAP 9.20.1 supports SVM migration for SVMs that host S3 NAS buckets on FlexVol volumes, allowing administrators to migrate SVMs without first removing S3 NAS configuration.

//ONTAPDOC-4075
a|
xref:../concepts/capacity-measurements.html[Simplified reporting of storage efficiency data reduction rates]
a|
The storage efficiency data reduction rate (DRR) provides a more precise assessment of ONTAP storage efficiency space savings by including only reducible data. In ONTAP 9.19.1 and earlier, the DRR includes both reducible and non-reducible data.

//ONTAPDOC-4052
a|
xref:../concepts/builtin-storage-efficiency-concept.html[Improved performance after migrating volumes from non-QAT systems to QAT systems]
a|
ONTAP reduces additional read latency and CPU usage that can occur after volumes are migrated from systems that do not support QuickAssist Technology (QAT) to systems that do. 

//ONTAPDOC-4052
a|
xref:../task_nas_file_system_analytics_view.html[File System Analytics access-time preservation]
a|
File System Analytics scans and System Manager File System Explorer browsing preserve directory access-time (atime) metadata. This helps maintain accurate atime values for archival, tiering, compliance, and data lifecycle workflows.

//ONTAPDOC-3984
