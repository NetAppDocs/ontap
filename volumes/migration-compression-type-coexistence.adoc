= Support for compression type coexistence during ONTAP volume migration
:icons: font
:imagesdir: ../media/

[.lead]
When a volume is migrated between ONTAP systems, the source volume might use a different data compression type than the destination volume.

Supported compression types include secondary, adaptive 8K, and temperature-sensitive storage (TSSE). During migration, these compression types can temporarily coexist on the destination volume as follows:

[options="header", cols="4"]
|===
|Source volume|Destination volume |Coexistence supported for migration|Application I/O read/write size

|Secondary compression type |TSSE/32k inline compression type|Yes|Auto
|Adaptive 8k compression type|TSSE/32k inline compression type|Yes|Auto
|Secondary compression type |Adaptive 8k compression type|No|Not supported
|===

.Migration from secondary and adaptive 8k compression to TSSE compression

Secondary and 8k adaptive volumes are progressively converted to TSSE/32k inline compression for QuickAssist Technology (QAT) and other supported systems through background processes after the migration or as data is rewritten to the destination volume during the migration.  

After a volume is migrated from secondary or adaptive 8K compression to TSSE compression, the *compression type* displayed in the `volume efficiency show` command output does not change even after all existing blocks have been converted. The compression type remains *secondary* for a converted secondary volume and *adaptive* for a converted adaptive 8K volume.

New data written to volumes converted from secondary or adaptive 8K compression is compressed with TSSE.

.Migration from secondary compression to adaptive 8k compression 

Direct coexistence of Secondary and Adaptive 8k compression on the same volume is not supported.
